# G3 capability-contract checkpoint

Status: in progress

Gate passed: false

Release ready: false

This checkpoint establishes the reviewed V4 capability contract and freezes
the full planned capability matrix. It does not claim that G3, every business
capability, or the release is complete.

## Included

- A versioned, data-only capability registry with stable capability IDs.
- The fixed V1 discovery and invocation command surface.
- A frozen matrix of exactly 102 stable capability IDs across every accounting
  domain required by the execution Goal.
- Eleven implemented read capabilities: `account.account.list`,
  `company.accounting_context.list`, `journal.list`, `tax.list`,
  `payment_term.list`, `currency.list`, `journal_entry.search`, and
  `journal_entry.get`, `report.trial_balance`, `report.balance_sheet`, and
  `report.profit_and_loss`;
  their stable IDs, sources, schemas, routing, and handler
  contracts remain frozen while G5 test and runtime-status metadata record real
  verification.
- 91 planned capabilities explicitly marked
  `disabled/implementation_pending`, with planned tests and no handler key.
- Draft 2020-12 request, response, and registry schemas enforced at runtime.
- A single-document JSON stdout contract and stable exit-code mapping.
- Company-scoped, database/user-bound cursor semantics.
- A registry-driven Pi Skill packaged with the wheel.
- A public-safe summary of the reviewed initial CLI-Anything generation
  checkpoint. The byte-exact raw baseline is retained outside the public Git
  tree for provenance and refinement because it contains environment-specific
  paths.

The remaining fixed write and operation commands are present as explicit
unavailable command shells. They do not perform writes.

## Deliberate limitations

- The ten public descriptors remain `unconfigured`, not globally `available`.
  Subsequent G5 work has validated its real bridge in the two private synthetic
  environments, while availability remains a runtime database/company/user
  decision.
- The remaining implementations and specialized schemas, and the write state
  machine remain pending; matrix registration alone does not make a capability
  callable.
- Branch coverage is currently 75%; the final G8 threshold remains 85%.
- The initial generator baseline is retained for provenance and refinement; it
  is not the authoritative runtime implementation.

No existing database, Odoo service, Odoo source tree, V2/V3 installation, or
legacy harness was modified by this checkpoint.
