# G5 real-read vertical-slice checkpoint

Status: `in_progress`

Gate passed: `false`

Release ready: `false`

This checkpoint proves the first seventeen formal V4 read capabilities through the real
local Odoo 19 bridge. It does not claim that all planned reads, reports, or G5
are complete.

## Implemented vertical slice

- `account.account.list`, `company.accounting_context.list`, `journal.list`,
  `tax.list`, `payment_term.list`, `currency.list`, `journal_entry.search`, and
  `journal_entry.get`, `report.trial_balance`, `report.balance_sheet`, and
  `report.profit_and_loss`, `report.cash_flow`, `report.tax`, and
  `user.accounting_access.inspect`, `company.accounting_configuration.inspect`,
  `diagnostic.accounting_environment.inspect`, and `partner.accounting.search` are
  dispatched through the allowlisted V4 control CLI,
  a single-document stdin/stdout JSON subprocess protocol, the Odoo 19 Python
  runtime, Registry/Environment, and their fixed real ORM models:
  `account.account`, `account.journal`, `account.tax`,
  `account.payment.term`/`account.payment.term.line`, `res.currency`,
  `account.move`, `account.move.line`, `res.company`, `res.users`,
  `ir.module.module`, `res.partner`, and the fixed Odoo financial-report definitions and
  `account.report` handlers.
- Runtime targets are resolved from an explicit database/company/user
  allowlist. The business Environment uses the configured non-superuser and
  company scope; none of the seventeen business reads uses `sudo`.
- Every business cursor executes `SET TRANSACTION READ ONLY`, then rolls back
  and closes. No general model/method dispatcher or direct business SQL is
  exposed.
- Company visibility, module state, ACL, page data, and the reported Odoo user
  ID are obtained by one allowlisted action in the same read-only transaction.
- An inactive requested Odoo language now returns the structured
  `language_unavailable` error instead of an opaque runtime failure or an
  implicit fallback.
