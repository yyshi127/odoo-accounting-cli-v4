This checkpoint proves the first five formal V4 read capabilities through the real
local Odoo 19 bridge. It does not claim that all planned reads, reports, or G5
are complete.

## Implemented vertical slice

- `account.account.list`, `journal.list`, `tax.list`, `payment_term.list`, and
  `currency.list` are dispatched through the allowlisted V4 control CLI,
  a single-document stdin/stdout JSON subprocess protocol, the Odoo 19 Python
  runtime, Registry/Environment, and their fixed real ORM models:
  `account.account`, `account.journal`, `account.tax`,
  `account.payment.term`/`account.payment.term.line`, and `res.currency`.
- Runtime targets are resolved from an explicit database/company/user
  allowlist. The business Environment uses the configured non-superuser and
  company scope; none of the five business reads uses `sudo`.
- Every business cursor executes `SET TRANSACTION READ ONLY`, then rolls back
  and closes. No general model/method dispatcher or direct business SQL is
  exposed.
- Company visibility, module state, ACL, page data, and the reported Odoo user
  ID are obtained by one allowlisted action in the same read-only transaction.
- An inactive requested Odoo language now returns the structured
  `language_unavailable` error instead of an opaque runtime failure or an
  implicit fallback.
